# Clash 转换器与在线记录管理实施计划

## 当前缺口

发布会同时创建文件订阅源和普通订阅。转换页面只用 Vue 组件变量保存本次生成的地址。管理动作分散在订阅源和订阅管理两个页面，发布记录没有明确归属。离线下载自行处理重名并生成分组，在线拉取经过通用导出流程，两者可能得到不同的节点名和分组。当前落库的是解析后的节点，无法还原用户最初粘贴的文本。

参考项目依据为 oldxianyu/vless-sub-converter 的 worker.js，版本 df58395。可借鉴自定义标识、防覆盖、固定订阅地址、客户端更新和按服务分流。它的页面只提供生成及复制，记录列表、编辑、撤销等管理能力需在本项目补齐。现有后台已要求登录发布，公开读取使用随机密钥。

## 页面与操作

| 入口 | 用户操作 | 完成后的可见结果 |
| --- | --- | --- |
| Clash 订阅转换器 → 在线记录（默认） | 搜索名称、按启用状态筛选、分页；空状态可直接新建 | 最近更新的记录排在前面。每条显示名称、节点数、状态、创建和更新时间 |
| 新建转换 | 自定义名称，粘贴链接列表、Base64 或 Clash YAML，也可从本地文件读入；预览解析结果 | 可查看成功及跳过数、失败的行号或节点序号和原因，以及 YAML。下载文件无需创建在线记录 |
| 发布 | 保存到在线记录 | 返回记录详情，有复制地址、导入 Clash、下载 YAML 三个入口。地址可手动选中复制，客户端可直接拉取 |
| 记录详情与编辑 | 改名、查看节点、增删或替换配置、预览差异后保存 | 显示新增、移除和修改的节点数，已安装的客户端下次刷新原地址即生效 |
| 状态和链接管理 | 停用、恢复、重置链接、删除 | 停用后拉取返回 404，恢复后原地址可用；重置后旧地址失效；删除前显示关联引用 |

名称用于列表和搜索，允许中文和重名；记录由独立 ID 区分，公开链接沿用随机密钥。重名发布可创建独立记录，编辑已有记录才会覆盖内容。记录详情和编辑支持直接刷新和返回列表。管理页摘要不携带节点凭据或完整订阅密钥。

## 实施顺序

1. **建立发布记录并处理历史数据。** 以现有 Subscription 作为公开地址及启停状态的唯一来源，增加一对一的转换记录元数据，关联文件源并记录创建时间、更新时间、版本和配置模板。新发布在一个事务内写入源、订阅和记录。旧版本缺少来源标记，可按单文件源、无账号及链路、原有命名等特征列出候选，让管理员选择“纳入转换器管理”；支持从已有文件订阅中选择曾经改名的记录。接管前检查引用及配置，保留原密钥。已有节点以可编辑的规范化 YAML 展示。历史时间未知时标注未知。迁移测试同时包含名称相似的普通订阅。
2. **统一转换与发布。** 在现有解析器之上增加带诊断的结果，保持原有解析入口契约。共享节点校验、重名处理、规则模板和 YAML 渲染；离线预览及下载使用同一结果。已发布记录按同一版本渲染在线地址和文件。支持完整配置和纯节点 YAML。对目前静默跳过的错误给出位置及原因，全部失败时禁止发布；有效节点与坏行混合时允许明确选择发布有效节点。
3. **提供专属管理接口。** 在现有 convert 接口旁增加记录列表、详情、更新和历史接管能力。复用已有启停、轮换、删除和公开拉取逻辑。列表只返回摘要，进入详情或复制时才取公开地址；管理操作沿用登录与 CSRF 校验。更新校验版本号，陈旧编辑返回 409，保留用户输入。一个发布请求以幂等键识别重试，双击或网络重试只创建一条。同名的独立请求分别保存。公开链接使用部署的 PUBLIC_BASE_URL。
4. **交付专属管理页面。** 在独立菜单下设置“在线记录”和“新建转换”，详情和编辑可通过路由直达。发布成功即展示新记录，列表可直接复制、下载、进入编辑。通用订阅列表对转换记录提供跳转，通用订阅源页也标明关联记录，涉及内容的修改统一进入转换器。覆盖首次使用、加载失败、空列表、移动端与复制失败场景。
5. **补齐配置模板。** 默认沿用项目现有的基础分流。另提供参考项目风格的增强分流，包含手动选节点、自动选择、Apple、Google、广告策略组及对应规则集。页面标明增强模板需要客户端拉取外部规则；保存选择后下载与在线配置保持一致。模板引用、分组名和重名节点一起校验。维持现有客户端更新间隔等真实元数据。
6. **处理资源引用与回归。** 删除记录遵守现有入口及链路的引用限制。在同一事务中仅清理转换器拥有且无其他引用的文件源。更新共享文件源时先复制到记录专用源，避免更改其他订阅。两套管理入口共用状态和引用检查。迁移后的旧记录先按原公开导出方式服务，切换模板或发布内容变更前展示差异。

## 数据流

```text
预览或直接下载 → 解析输入并报告问题 → 确定节点、重名和模板 → 输出 YAML
首次发布 → 校验相同转换结果 → 事务保存源、订阅、转换记录 → 打开详情
编辑保存 → 校验记录版本及源引用 → 事务替换节点和元数据 → 原链接读取新版本
客户端拉取 → 验证密钥与启用状态 → 读取已提交版本 → 输出该版本 YAML
```

## 验收场景

- 从空列表发布名为“手机”的订阅，复制链接；刷新后台、重新登录、重启服务后能找到同一记录，另一台能访问服务的设备可拉取配置。
- 仅下载文件后查列表，记录数不变。相同输入和模板生成的预览、文件、公开完整配置逐项一致，纯节点输出只含 proxies。
- 使用 Reality + TCP + Vision、Reality + gRPC、TLS + gRPC、同名节点和无效链接验证。短 ID 保留前导零，gRPC 服务名与指纹正确。两种模板各用 Mihomo 校验，实机导入与真实握手分别记录验证结果。
- 编辑节点后从原地址刷新能拿到新内容；提交无效配置、重复提交、两个窗口并发编辑都不会破坏已有可用版本。
- 验证停用与恢复、重置链接、删除、共享源及链路引用。从通用管理入口发起同类操作，结果与专属管理页一致。
- 在旧库副本升级，核对原公开 URL、普通聚合订阅和候选接管流程。构建前端，执行后端回归与浏览器“发布 → 刷新 → 查记录 → 改节点 → 重拉 → 撤销”全流程。
