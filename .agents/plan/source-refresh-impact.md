# 订阅源刷新影响分析：实施计划

## 交付目标与边界

让管理员从“订阅源刷新成功”看到“谁受影响、哪一跳要改”，然后在现有编辑器验证替代方案。首版是刷新后的只读报告，不拦截发布、不自动改配、不改变公开订阅格式；不引入图数据库、新测速任务或全量配置快照。源删除、停用、替换 URL、手工策略编辑不作为本次刷新事件；换址后首次拉取重建基线，不归因为上游删除。

## 核心数据流（伪代码）

```text
解析成功 → 在同一份只读基线上建立 before / after，仅目标源数据不同
          → 原子提交新节点、源版本与待分析标记
          → 对依赖该源的订阅和链路比较前后有效候选、逐跳及路径状态
          → 仅在源版本仍匹配时写入脱敏报告，否则丢弃过期结果
解析失败 → 保留节点与成功报告，刷新错误单独展示
```

首版采用按源依赖范围内的内存比较，不维护独立依赖图。批量载入配置、探测缓存及相关来源，按订阅复用候选计算，避免每跳单独查库；在合成大样本记录分析耗时和查询数。分析未完成而进程重启时，标记该版本未完成，不拿旧报告冒充本轮结果。存储、日志及接口只含必要资源标识、版本、位置、计数及枚举原因；不留原始节点、凭据、订阅 URL 或完整配置。历史报告标记为刷新当时的观察，不代表此刻状态。

## 判定与验收样例

- 两条路径：移除主路径第二跳所需的固定节点，备用引用仍完整 → “主路径受损，备用引用完整，未实测”；只移除备用必需节点 → “备用受损”；全部路径从有引用可解析变为无一可解析 → 最高优先级。不能用“已切换”代替实际运行事件。
- 多源补位、节点只改名且筛选未变 → 不报固定跳失效；同名但 key 不同 → 不自动替换。入口候选由三变二但策略仍可选 → 只提示缩减；指定候选消失即使池中还有其他节点，仍按指定策略判失效。
- 从文件源重传上述数据：订阅源页打开报告 → 定位主路径第二跳 → 手动选择替代节点 → 运行草稿诊断 → 取消。确认无保存请求、配置 revision 未变；即使没有可用内核仍能查看影响报告，诊断不可用须明确提示。
